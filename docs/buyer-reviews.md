# Buyer product reviews

After a successful receipt confirmation on a genuine paid purchase, CampusMart opens an optional review dialog for that order item's product. Buyers choose one to five stars, optionally add up to 2,000 characters, and can select Not now or Escape. Received items retain a Rate this item/Edit review action in both order lists and order details. Existing reviewers are not automatically prompted again for the same product.

The original database cm_review_product RPC remains the authoritative write path. It checks the signed-in buyer's paid, received purchase for the exact product, excludes Paystack test payments, serializes writes by locking the product, and updates that buyer's existing review rather than adding another. Existing database triggers reject vendor self-reviews and derive averages/counts from the source review rows, including after edits and administrative removal. No rating is weighted by order quantity; each buyer contributes one review per product. Trial orders remain unpaid and the UI excludes both trials and test orders.

Product pages show public star ratings, comments and dates with 20 reviews per page. An independent own-review query pre-fills the editor even if the buyer's review is on an older page. Product summaries use the database aggregate across all reviews, displayed to one decimal place, not the current page's average. Review text is rendered as text; buyer emails and names are not added to the public display.

Own-review lookups are batched by product and scoped to the signed-in user. Read failures suppress the order-page prompt rather than guessing an existing review is absent; the existing product review link remains available. Save failures keep the rating/comment draft. Successful saves invalidate the product and relevant order views. The prompt does not initiate a payout, affect refund rights or force positive feedback.

No new SQL migration or credentials are needed: this extends the existing buyer feature, review-integrity and payment migrations. The database regression runs the actual current cm_review_product function, alongside the existing aggregate/author triggers, in an isolated PostgreSQL test database. Tests cover product separation, unreceived/unpaid/test purchase rejection, self-reviews, one-to-five rating bounds, optional comments, edit identity/count preservation, fractional averages and removal. Production browser checks cover receipt prompts, skipping/returning, optional comments, public pagination, older-review editing, test exclusion and mobile failed-save recovery. No real reviews or payments were created during verification.
