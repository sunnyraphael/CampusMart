# CampusMart website review — 1 November 2026

This is a repository review and local test report, not a certification that the live site is bug-free or legally compliant. No production customer records, credentials, live database policies, hosting controls or Paystack account were inspected. No live SQL, payment, refund or deployment was performed. Recommendations below have not been implemented unless explicitly marked as part of this change.

## Changes requested and implemented

- Mobile buyer navigation now has four equal-width tabs: Home, Categories, Listings and Deals. A labelled three-line Menu button sits beside search.
- Orders, messages and unread counts, notifications, favorites, saved searches, profile, support and the vendor workspace are in the menu. Admin appears only for an administrator; the actual route still independently enforces admin access.
- Settings & privacy and Sign out are adjacent. Signed-out users get Log in/Create account. The menu supports keyboard navigation, Escape, outside dismissal, focus return and scrolling on short screens.
- Order details has Cancellation options with a confirmation dialog. The server checks ownership, the 30-minute deadline and every item's status. Pending/confirmed trials can be cancelled; dispatch or pickup readiness blocks cancellation. The whole order is cancelled atomically, vendors are notified and tracking records the change. Retries do not repeat the cancellation.
- Trial refunds and retained fees are both zero. Trial cancellation does not restore stock that was never reserved or create real financial transactions. Audited cancelled trials no longer incorrectly prevent account closure.
- Refund policy and Help explain the process. The 30-minute tool does not remove statutory remedies. Real paid cancellation fails closed until refund/payment and inventory integration exists.
- Empty checkout keeps its page heading; listing cart actions remain disabled until interactive. Layout setup verifies the add-to-cart result before navigating.
- Lint excludes generated `.next-e2e` and `.next-build-check` files, alongside the normal `.next` ignore; application lint rules remain enabled.

Apply `supabase/migrations/202611010004_buyer_order_cancellation.sql` **once**, after all previous migrations. This file has only been tested locally. Without it, cancellation reports an unavailable service and does not silently change orders. Existing orders may already be outside the window; use a new trial to test.

## Cancellation and future Paystack design

The interpretation used is **within 30 minutes after placing an order**, not a waiting period starting after 30 minutes. Dispatch/readiness ends automatic cancellation. Returns, non-delivery and statutory complaints remain available through support afterwards.

For a later live implementation: lock the order/items, recheck eligibility, calculate the refund from the immutable payment/fee snapshot, record a unique refund job and block fulfilment/vendor release in the same database transaction. A server worker calls Paystack's Refund API with the original transaction reference and exact amount in kobo. Persist and reconcile provider references; verify signed webhook events and deduplicate them. A timeout must trigger reconciliation before another refund request. Show pending/processing/needs-attention/failed/processed honestly. Handle inventory reservations once, and maintain an admin exception queue. Provider initiation may be automatic; the bank credit is not necessarily immediate.

Before activating a real fee-retention rule, version and present the actual payment/refund terms for acceptance. The current draft describes a future conditional rule and does not authorize charging trial users or silently changing existing paid-order terms.

No live Paystack callback was added during this task. Current real paid orders direct the buyer to support rather than promising a refund that has not been sent.

## Sources and legal limits

- [FCCPC consumer rights](https://fccpc.gov.ng/consumers/consumer-rights-responsibilities/rights-responsibilities/): written, understandable prices/conditions; reasonable cancellation charges; circumstances requiring full refunds; accurate claims and limits on liability exclusions.
- [Nigeria Data Protection Act, NDPC publication](https://ndpc.gov.ng/download/nigeria-data-protection-act-2023) and [NDPC guidance issued March 2025](https://ndpc.gov.ng/wp-content/uploads/2025/03/NDP-ACT-GAID-2025-MARCH-20TH.pdf): privacy obligations must match actual operations. A banner alone does not establish compliance.
- [Paystack terms](https://paystack.com/terms): age restrictions and merchant obligations. Guardian marketplace consent does not amend these terms.
- [Paystack refunds API workflow](https://paystack.com/docs/payments/refunds/): full/partial refunds, asynchronous status changes and webhook events; processed refunds may still take time to reach the buyer.
- [Paystack refund support guidance](https://support.paystack.com/en/articles/2127106): the provider does not return its original processing charge. That is a merchant cost rule, not independent permission to retain a CampusMart buyer service fee.

The report identifies issues that could cause consumer complaints, financial loss or regulatory exposure. It does not predict litigation or replace a qualified review of the actual Nigerian business, hosting and payment arrangements.
