## Changes

1. Login redirects now build a URL from the destination, preserving its path, query parameters and fragment. Safe local redirect validation remains in place.
2. Recognized authentication/profile callback errors remain visible even when a session already exists. The login page distinguishes a failed profile lookup and provides a support link.
3. /start-selling lets an existing buyer explicitly enable vendor access on their own account, preserving their purchases and saved data. The RPC only permits buyer/student to vendor; it accepts no target user or target role and never grants admin membership. Homepage, header and footer selling links use this entry point. Existing logged-in registration links with role=vendor also resolve to it.
4. Onboarding now has a server-side gate. Existing stores redirect to the dashboard before a form is rendered. The form is preserved in OnboardingClient.tsx. A second existence check at submission handles another tab finishing setup and redirects instead of overwriting the store.
5. Vendor headings reflect the current page, including new/edit listings and packing slips. View Store and My Store use the authenticated vendor store ID instead of linking home. Mobile navigation closes when its links are selected.
6. Listing deletion uses an owner-scoped database RPC and a durable image cleanup queue. Database triggers also capture photos removed during edits. Existing duplicated listings keep shared images. When the last reference is removed, cleanup claims the file before calling the Storage API. Stale URLs cannot be attached while queued/removing or after deletion. Failed API calls remain retryable using Clean up unused photos on the listings page. Storage policies permit cleanup only for the owning vendor's claimed, unreferenced product images. KYC documents and other vendors' folders are excluded.
